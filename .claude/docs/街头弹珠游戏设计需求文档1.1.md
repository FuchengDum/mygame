# 项目代号：街头弹珠 (Project: Marble Street)
## 游戏设计需求文档 v1.1（H5 + Phaser 3 技术栈定版｜移动端补强版）

### 0. 文档信息
- 版本：v1.1
- 目标：在“手机浏览器”场景下，以可落地的方式验证“拉弓手感 + 拟真氛围 + 完整对局闭环”
- 范围：MVP（街头霸王/相扑模式）为强约束；Phase 2 仅作为后续规划，不得反向侵入 MVP 排期
- 备注：本版补充移动端关键约束（安全区/横竖屏/触控穿透/相机视野），并新增 5.6“竞技场尺寸与移动端适配（MVP 强约束）”，避免按屏幕 1:1 导致场地过小与跨机型不公平

---

## 1. 项目愿景 (Vision)
打造一款怀旧、极致拟真的街头弹珠 H5 游戏，核心卖点：
- 触感视觉化：把“拉弓发射”的触觉通过视觉、音频、震动反馈显性化
- 微缩摄影级氛围：黄金时刻、尘埃光束、浅景深、写实材质瑕疵
- 街头竞技的紧张感：同屏轮流对战、节奏紧凑、结果清晰、可复盘可调参

设计原则（MVP 必须遵守）：
- 可玩性优先于拟真：所有“拟真特效”必须可降级，不得牺牲稳定帧率与可读性
- 手感可控：物理与误差源必须“可解释、可调参、尽量可复现”
- Web 现实主义：以 H5 性能与浏览器限制为边界进行设计，不做不可落地的承诺
- 移动端优先：所有 UI/镜头/输入设计以拇指触控与小屏可读性为第一约束，PC 仅作为兼容运行目标

## 2. 目标平台与硬约束 (Platform & Constraints)

### 2.1 运行平台
- 形态：手机浏览器 H5（纯前端 SPA）
- 浏览器：iOS Safari、Android Chrome、微信内置浏览器（WeChat WebView）
- 渲染：WebGL（优先 WebGL2；必须具备 WebGL1/低端机降级策略或明确提示）
- 输入：触摸屏虚拟控制器（单指拖拽“拉弓”）
- 网络：不依赖网络服务；允许离线游玩（静态资源首次加载后）
- 屏幕方向（MVP 必须明确）：
  - 默认：竖屏 Portrait（优先适配单手操作与 pass-and-play）
  - 横屏：MVP 可不支持；如用户旋转为横屏，必须提示并引导回竖屏（不得出现拉伸变形或坐标错乱）

### 2.2 性能指标（MVP 必须满足）
- 帧率：目标 60fps；最低可接受 30fps（低于阈值必须自动降级特效/粒子）
- 物理：固定时间步（Fixed Timestep），避免随帧率漂移导致手感不一致
- 内存：对局资源按需加载/释放；微信 WebView 需重点防内存膨胀
- 画质分级：至少高/低两档；默认自动选择，用户可手动切换
- 分辨率策略（移动端必须纳入）：
  - 允许内部渲染分辨率缩放（Resolution Scale），避免高 DPR 机型直接按 devicePixelRatio 全开导致掉帧
  - 低画质默认降低内部分辨率并减少后处理（DoF/体积光/粒子）

### 2.3 浏览器限制（MVP 必须纳入方案）
- 音频：WebAudio 需用户手势解锁（点击“开始游戏”后初始化音频上下文）
- 后台：切到后台会挂起/丢失上下文的情况需可恢复（至少回到菜单/重进对局不崩）
- 触控：需处理滚动穿透、误触、不同采样率导致的力度差异
- 视口与地址栏（移动端必须纳入）：
  - iOS Safari/微信 WebView 可能因地址栏收起/弹出导致 viewport 高度变化；对局中必须稳定画布尺寸与坐标映射（重算相机与输入换算）
  - 禁止对局中出现页面滚动/回弹（需设置 `touch-action` 与事件 preventDefault 策略）

### 2.4 安全区与可达性（移动端硬约束）
- 安全区：适配刘海/圆角屏安全区（`safe-area-inset-*`）；HUD 不得贴边遮挡或被系统手势区域吞掉
- 可达性：核心操作区与关键提示尽量位于屏幕中下部可达区域；避免重要信息靠近顶栏与边缘手势区
- 手指遮挡：瞄准/力度反馈不得依赖“手指正下方可见”，需要在弹珠附近或上方提供清晰反馈（见 6.x 与 8.4）

## 3. 技术栈与工程边界 (Tech Stack)

### 3.1 既定技术栈（必须遵守）
- React 18 + TypeScript + Vite
- Tailwind CSS（用于 React UI；不介入 Phaser 场景渲染）
- Zustand（设置、对局状态、结算统计）
- React Router v6（页面路由与生命周期）
- Phaser 3（对局场景、物理、输入、相机、粒子、音效触发）

### 3.2 架构职责边界（MVP 必须）
- React：菜单/设置/教程/结算 UI、可访问性、配置面板、路由与页面结构
- Phaser：游戏循环、物理模拟、碰撞判定、镜头、对局内特效、音效触发与节奏控制
- 约束：Phaser Canvas 作为 React 组件挂载；UI 状态变化不得导致 Phaser 反复重建（除非切路由）

### 3.3 无后端约束（MVP 必须声明）
- 不做：登录、云存档、排行榜、在线对战、付费与商城
- 数据持久化：仅本地（`localStorage`/`IndexedDB`），清缓存丢档可接受（设置页提示）

## 4. 开发路线图 (Roadmap)

### 4.1 第一阶段：MVP 核心验证版（本轮交付）
目标：完成“可玩一整局”的同屏轮流对战，并达到稳定手感与氛围标杆
- 模式：街头霸王（相扑）Street Sumo
- 对战：同屏轮流回合制（pass-and-play），不联网
- 地图：标准平整泥土地（无复杂地形）
- 操作：单指拖拽拉弓 + 瞄准线（短预测）+ 概率散布圈
- 特效：以“结果写实”为导向（伪焦散/轻量 DoF/粒子降级）

### 4.2 第二阶段：完整商业版（规划，不进入 MVP）
- 新模式：进洞为王（Tiger Hole）
- 赌注/收集：本地收集可先做；若线上化需新增后端与公平性设计（另立项）
- 材质物理：碎裂、铁球/玻璃球差异
- 交互：摄像头 AI 手势识别（需隐私合规与触控回退）
- 地图：复杂地形（泥坑、下水道、路牙子）

## 5. MVP 玩法与规则（Street Sumo）

### 5.1 对局形态：同屏轮流回合制
- 玩家：2 名本地玩家（A/B）
- 回合：A 发射 -> 结算运动停止 -> B 发射 -> 循环
- 换手信息控制：
  - 仅当前玩家可见“瞄准线/力度 UI”
  - 回合结束自动隐藏辅助信息（减少偷看）

### 5.2 胜利条件与出界判定
- 胜利：将对方弹珠击出界外，且自己未出界
- 出界：球心越过边界线即判出界（球心判定法）
- 平局/争议处理（MVP 强制明确）：
  - 同一回合双方出界：进入“加赛一局”（推荐默认），直到分出胜负
- 边界表现（MVP）：
  - 可见边界线（清晰对比度）
  - 不设置“弹回墙”（避免边界碰撞争议与物理不稳定）

### 5.3 回合流程与超时
- 回合阶段：
  1) 回合开始（镜头复位、提示当前玩家）
  2) 瞄准/拉弓（显示短轨迹预测与概率圈）
  3) 松手发射
  4) 运动与碰撞
  5) 停止判定（速度低于阈值并持续 N 秒）
  6) 回合结算/换手或结束比赛
- 瞄准倒计时：默认 10 秒（可配置）
- 超时处理：自动按当前力度/角度发射（避免卡局）

### 5.4 奖励回合（Bonus Turn）
- 触发：有效击中对手（对手未出界）
- 连击衰减：
  - 第 2 次奖励回合：瞄准倒计时减半（明确：减半的是瞄准时间）
- 连击上限：最多 2 连（MVP 默认，防无限控场）

### 5.5 结算与统计（MVP）
- 结算内容：
  - 胜负/加赛结果
  - 回合数、有效命中数、出界次数
  - 击飞距离、完美压线次数
- 指标口径（MVP 固定）：
  - 击飞距离：对手出界瞬间位置与其初始位置的水平距离
  - 完美压线：球心到边界线距离 < 阈值且未出界（阈值可配置）

### 5.6 竞技场尺寸与移动端适配（MVP 强约束）
- 背景问题：移动端若按“屏幕像素 1:1”直接定义物理世界与出界边界，会导致竞技场过小、轻微碰撞即出界、调参空间被压缩，并在不同机型上产生显著不公平（小屏更容易出界）。
- 核心原则（必须遵守）：
  - 物理世界尺寸与屏幕显示尺寸必须解耦；屏幕是相机视口，不是世界边界。
  - 出界判定基于世界坐标的“边界线”，与屏幕边缘无关。
  - 场地尺度必须用“弹珠半径 R（世界单位）”做基准，禁止用屏幕像素直接定义竞技场半径/宽度。
- 默认场地规范（MVP 初始值，可配置可调参）：
  - 竞技场形状：圆形相扑圈（默认）。
  - 竞技场可用半径：`arenaRadiusInR = 22`（建议可调范围 18..26）。
  - 镜头安全边距：`cameraMarginInR = 3`（建议可调范围 2..4，用于边界线厚度、UI 遮挡余量、镜头抖动安全区）。
  - 初始站位半径：`spawnRadiusInR = 10`（建议可调范围 9..12），双方沿直径相对站位。
- 出界与可视性强约束：
  - 出界判定仍按 5.2：球心越过边界线即判出界（球心判定法）。
  - 在飞行/运动阶段（对局状态 `simulating`）必须保证任意目标机型都能看到“完整边界线 + 镜头安全边距”，否则视为可读性缺陷。
- 相机缩放适配（规范，确保跨机型一致）：
  - 世界直径定义：`worldDiameter = 2 * (arenaRadiusInR + cameraMarginInR) * R`。
  - 运动态缩放：`zoomSim = min(viewW / worldDiameter, viewH / worldDiameter)`（以完整显示边界为目标）。
  - 瞄准态允许适度拉近：`zoomAim = zoomSim * aimZoomFactor`，其中 `aimZoomFactor` 建议 1.10..1.25，但不得导致边界/对手球不可读。
- 触控遮挡与操作区建议（MVP 不强制二选一，但必须明确采用其一并保持一致）：
  - 方案 A（默认）：全屏显示竞技场；拖拽可发生在任意区域或限制在底部约 40% 区域；HUD 避开底部拇指遮挡带。
  - 方案 B（可选，体验更稳）：底部“拉弓控制垫”（占屏高约 25%..35%）专用于拖拽采样，上方区域仅用于观看竞技场；注意此方案改变的是 UI/输入布局，世界尺寸与出界规则不变。

## 6. 核心操作与输入系统 (Controls)

### 6.1 单指拖拽“拉弓”
- 操作映射：
  - 后拉距离 -> 发射力度
  - 左右偏移 -> 发射角度
  - 松手 -> 发射
- 距离归一化：
  - 使用屏幕短边比例归一化拖拽距离，保证不同设备力度一致
- 力度曲线（MVP 必须配置化）：
  - 默认采用“前段细腻、后段增强”的非线性曲线（指数/分段均可）
- 灵敏度档位：至少 3 档（低/中/高）

### 6.2 触感视觉化反馈（MVP 验收口径）
- 必须具备的反馈层级：
  - 姿态：手/弹珠蓄力姿态随拖拽实时变化
  - 力度：力度越大，蓄力表现越强（形变/压痕/发射瞬间的能量感）
- 可迭代细节（非 MVP 阻塞）：
  - 指尖泛红、皮肤褶皱堆积、细微汗光

### 6.3 触觉反馈（Haptics）
- 使用 `navigator.vibrate`（支持则启用，不支持则静默）
- 震动事件：
  - 发射：短促
  - 强碰撞：中等
  - 出界/胜负：清晰的长短组合
- 设置项：可关闭（默认开）

### 6.4 移动端触控细则（MVP 必须明确）
- 多指：仅采样第一触点；第二触点出现时不得导致力度跳变或镜头抖动
- 触控穿透：对局中禁止页面滚动与缩放手势干扰；需要对 Canvas 与操作区施加 `touch-action: none` 与必要的事件拦截策略
- 误触容错：
  - `pointerdown` 必须落在“允许操作区”才开始蓄力（由 5.6 方案 A/B 决定）
  - `pointercancel`/来电/切后台导致的输入中断：必须安全复位到“未蓄力”状态，不得自动发射
- 遮挡处理：瞄准线/力度数值/概率圈等关键反馈需出现在弹珠附近或其上方偏移位置，避免被手指覆盖

## 7. 物理与碰撞系统 (Physics)

### 7.1 基础碰撞（MVP）
- 弹珠 vs 弹珠：弹性碰撞 + 可调能量损失（阻尼）
- 弹珠 vs 地面：摩擦与滚动阻力
- 必须配置化的参数（至少）：
  - 质量、摩擦、弹性、线性阻尼、角阻尼、最小速度阈值（静止判定）

### 7.2 地面不平整（MVP：可控噪声）
- 禁止纯随机扰动（会伤害竞技学习与调试）
- 采用 seed 驱动的确定性微扰：
  - 同一局内一致、可复现、可调参
  - 可为后续“练习/竞技”模式预留开关结构（MVP 可先只做默认值）

### 7.3 辅助瞄准（MVP）
- 轨迹预测：仅显示前 0.5m 的预测轨迹
- 概率散布圈：表示不确定性，但不显示最终落点
- 误差来源必须可解释且可调：
  - 输入抖动（采样/手指稳定性）
  - 地面微扰（seed）
  - 可选：初始旋转扰动（MVP 可不做）

## 8. 视觉与美术表现（Web 可落地）

### 8.1 总体风格
- 极致拟真 3D 的“视觉目标”保留，但 MVP 的实现以“2.5D/轻量 shader/贴花”达成写实结果为准
- 原则：效果必须可分级、可关闭、可在中端机稳定运行

### 8.2 弹珠（Hero Asset）
- 必须：
  - 玻璃质感（反射/高光/透感），内部花纹可读
  - 表面瑕疵：微磨损、划痕、气泡（可贴图实现）
- 焦散（Caustics）：
  - MVP：伪焦散（贴花/投影/预烘焙光斑序列），必须可关闭
  - 高画质：允许增强实现，但不得成为验收阻塞

### 8.3 场景与光照
- 地面：压实泥土地（砂砾与干裂纹理明确可见）
- 光照：黄金时刻（暖色调、长阴影）
- 氛围：尘埃光束（粒子/体积近似，低画质关闭或极简）

### 8.4 摄像机（可玩性优先）
- 瞄准态：手部后上方 45 度微距；浅景深可用但不得遮挡边界/对手球可读性
- 飞行态：平滑跟随；镜头晃动强度可配置/可关闭
- 击中特写：慢动作 + 冲击抖动
  - 触发门槛：仅高能量碰撞/关键击飞触发，避免频繁打断节奏
- 移动端硬约束（补强）：
  - 运动态（`simulating`）必须完整显示出界边界线（含 5.6 的 `cameraMarginInR` 余量）
  - HUD/安全区不得覆盖边界线关键区域；若覆盖必须自动抬升/重排 HUD

### 8.5 手部表现（MVP 优先级）
- 必须：动作可信、接触关系正确、蓄力张力明确
- 非阻塞：指纹、倒刺等超高频细节（后续迭代）

## 9. 音效设计 (Audio)

### 9.1 碰撞音效
- 按材质与力度分层（至少区分：玻璃-玻璃、玻璃-地面/石）
- 多次撞击混音：
  - 必须做限幅/压缩策略，避免手机外放爆音
  - 允许并发但要有上限（避免“机关枪”式叠加）

### 9.2 环境音与 UI
- 环境音：蝉鸣、远处车铃、风吹树叶（营造放学后街头氛围）
- UI：粉笔写字音（确认/取消/结算）
- Web 解锁策略：点击“开始游戏”后初始化音频；提供静音按钮并记忆设置

## 10. UI/UX 页面与流程（React Router + React UI）

### 10.1 页面（MVP）
- `/` 主菜单：开始对局、设置、玩法说明（简版）
- `/match/local` 对局：Phaser Canvas + 最小必要 HUD（回合、倒计时、玩家提示）
- `/settings` 设置：画质档位、镜头晃动、音量、震动、灵敏度、辅助线开关

### 10.2 对局 HUD（MVP）
- 必须显示：当前玩家（A/B）、回合倒计时、奖励回合提示、胜负/加赛提示
- 辅助线可见性：仅当前玩家回合显示
- 移动端布局约束（补强）：
  - HUD 遵循安全区（刘海/圆角屏）；不得贴顶遮挡或被系统手势区域吞掉
  - 重要提示（回合归属、倒计时）在小屏上优先保证字号与对比度，不得因美术风格牺牲可读性

## 11. 状态管理、存档与可复现性（Zustand + 本地存储）

### 11.1 Zustand Store（MVP 至少包含）
- `settings`：
  - 画质档位（高/低）
  - DoF/镜头晃动（开关或强度）
  - 音量、静音
  - 震动开关
  - 灵敏度档
  - 辅助线开关
- `match`：
  - 当前局 seed
  - 当前玩家、回合数、奖励回合计数
  - 统计数据、结算结果

### 11.2 本地持久化
- 持久化范围：`settings` 必须持久化；`match` 可不持久化（MVP 允许刷新即丢局）
- 存储介质：优先 `localStorage`（设置体积小）；后续资源或回放才考虑 `IndexedDB`

### 11.3 可复现性要求（MVP 推荐达成）
- 同设备同浏览器内：相同 seed + 相同输入轨迹应尽量复现结果（至少误差可控）
- 地面微扰、概率圈误差等必须由 seed 驱动并记录在 `match.seed`

---

## 12. 调参系统与验收标准 (Tuning & Acceptance)

### 12.1 调参配置化（MVP 强制）
关键参数必须以配置形式存在（JSON/配置模块均可），可在不改核心逻辑的情况下调整：
- 发射力度曲线、角度灵敏度
- 摩擦/弹性/阻尼
- 地面噪声强度
- 回合时间、停球阈值与持续时间 N
- 慢动作触发阈值、持续时间、冷却
- 场地与镜头（新增，来自 5.6）：
  - `arenaRadiusInR`、`spawnRadiusInR`、`cameraMarginInR`
  - `aimZoomFactor`（瞄准态相对运动态缩放系数）
  - （可选）渲染分辨率缩放档位（高/低画质对应不同 scale）

### 12.2 MVP 验收标准（硬指标）
- 可用性：完成“进入游戏 -> 开始对局 -> 打完一局 -> 结算 -> 再来一局”闭环无阻断
- 性能：目标机型稳定 60fps；低端机自动降级保持 30fps 且无明显卡顿尖峰
- 稳定性：连续 10 局无穿透、弹珠消失、回合无法结束、音频崩溃
- 一致性：同等拖拽距离在不同设备上力度观感一致（在可接受误差范围内）
- 可读性：边界线、对手球在瞄准态与飞行态均清晰可辨（浅景深不许遮挡关键信息）
- 移动端适配（新增硬指标）：
  - 竖屏下任意目标机型在运动态必须完整显示出界边界线（含安全边距），不得因屏幕小导致“场地变小”
  - 刘海/圆角屏安全区适配正确，HUD 不遮挡边界关键区域
  - 对局中禁止页面滚动/回弹导致的输入漂移或坐标错乱

## 13. 风险清单与降级策略（MVP 必须预置）

- Web 高成本效果（DoF、体积光、真实焦散）：
  - 必须分级与开关；低画质默认关闭重特效
- 写实手部成本过高：
  - MVP 以动作可信与反馈明确为验收；微细节后置
- 物理随机影响公平：
  - 禁止纯随机；改为 seed 驱动确定性微扰
- 微信/浏览器音频限制：
  - 以“开始游戏”手势解锁音频；提供明确提示与静音记忆
- 内存与生命周期：
  - 路由切换时销毁 Phaser 实例并释放资源，避免 WebView 累积泄漏
- 移动端视口与旋转风险（新增）：
  - 地址栏/底栏变化导致 viewport 抖动：需要统一 resize 处理与相机/输入换算重算
  - 横竖屏切换：MVP 仅支持竖屏时必须有明确引导与保护，不得进入不可玩状态

## 14. 明确不在 MVP 范围（Out of Scope）
- 联网对战、排行榜、账号体系、云存档、支付与商城
- 摄像头手势识别（Phase 2 才评估）
- 弹珠碎裂与复杂材质体系（Phase 2）
- 复杂地形与多地图（MVP 仅平整泥土地）
